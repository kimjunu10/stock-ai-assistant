## 3. 정답 확정 방법

**RAG 가 생성한 답변은 쓰지 않았다. 검색도 돌리지 않았다.** DB 원본에서
결정적으로 유도되는 식별자만 확정했다(검색 결과 1위 자동 채택 없음).

### 뉴스

`news_clusters.id` → `rag_documents`(`source_type='news_event'`, `source_pk=cluster_id`,
`is_current=true`) → 그 문서의 활성 `rag_chunks.id` 전체를 정답으로 삼았다.

확정 전 다음을 모두 확인했다.

- 사건 요약 상태가 `success`
- 현재 문서(`is_current`)가 존재
- 활성 청크가 1건 이상 존재
- 질문 종목 = 사건 종목 = 문서 종목 = 청크 종목
- 사건 날짜·감성·기사 수를 근거에 기록

사건이 여러 청크로 쪼개진 경우 **전부 정답 후보로 남겼다**(1건만 고르면 임의 선택이 된다).

### 증권사 리포트

`research_reports.id` → `rag_chunks.source_locator->>'report_id'` 로 청크를 찾고,
그중 **목표주가 숫자가 본문에 실제로 있는 청크만** 근거로 확정했다.

- 리포트 청크의 `page_start`/`page_end` 컬럼은 **전부 NULL**이다(4,350건 중 0건).
  페이지는 `source_locator` JSON 의 `page_number` 에 있어 이것을 썼다.
- `target_price_status='stated'` 인 것만 인정했다.
- 근거 청크의 페이지가 PDF 페이지 수를 넘지 않는지 확인했다.
- 목표주가는 **전망값**이며 실제 거래가가 아님을 근거에 명시했다.

목표주가 숫자가 어느 청크 본문에도 없으면 확정하지 않도록 했다. 실제로 DB 전체에는
그런 리포트가 존재하지만(하나증권 360,000 / 미래에셋 70,000 등), **이번 20건은 모두
2~4개 청크에 목표주가 숫자가 실재해 확정 조건을 만족했다.**

### 복합 질문

복합 질문은 하위 질문마다 정답 문서가 달라 **단일 정답 식별자를 만들 수 없다.**
정답 식별자를 억지로 채우는 대신, §3 이 요구하는 나머지 라벨 항목이 모두 갖춰졌는지
확인해 확정했다.

- 필수 Tool 2개 이상
- 기대 입력 조건
- 허용 출처 종류
- 대상 종목

정답 식별자를 두지 않았다는 사실을 라벨 근거에 명시했다. 이 20건은 **검색 Recall 분모에서
제외**되고, 필수 Tool 호출·입력 조건·출처 종류로 채점된다.

## 7. 발견한 운영 코드 문제

**수정하지 않고 기록만 남긴다**(§6 수정 금지 준수).

1. **리포트 청크의 `page_start`/`page_end` 가 전부 NULL** — 리포트 청크 4,350건 중
   페이지 컬럼이 채워진 건이 0건이다. 페이지 정보는 `source_locator` JSON 에만 있다.
   컬럼으로 페이지 필터를 거는 코드가 있다면 동작하지 않는다.
2. **`research_reports.target_price_source_chunk_id` 가 비어 있다** — 목표주가 근거
   청크를 가리키는 컬럼인데 표본에서 NULL 이었다. 이번 검토에서는 본문 대조로 우회했다.
3. **목표주가 근거 청크가 없는 리포트가 존재한다** — `target_price_status='stated'` 인데
   목표주가 숫자가 어느 청크 본문에도 없는 리포트가 DB 에 있다(하나증권 360,000 /
   미래에셋증권 70,000 등). 목표주가 추출과 청크 색인이 어긋난 것으로 보인다.
   이번 평가셋 20건에는 해당 리포트가 포함되지 않았다.

이전 단계에서 기록한 관찰(용어 설명 답변에 대한 검증기의 "재무성 숫자 근거 없음" 오탐)도
그대로 남아 있다.
