### 4.1 검증기가 답변을 제거 — 22건 (가장 심각)

**기대**: "미래에셋증권에서 SK하이닉스 목표주가 얼마로 봤어?" → 4,200,000원 답변
**실제**: 정답 리포트(미래에셋 2026-07-14)를 **정확히 검색했는데**
"일부 증권사의 구조화된 목표주가를 확인할 수 없어 해당 수치는 제외했습니다"로 끝남

```
tool trace: search_research_reports(stock_code=000660) → ok
sources: 미래에셋증권 2026-07-14 p.8, 대신증권 2026-07-07 p.6, ...
validation_errors: ["Tool 결과에 없는 증권사를 답변에 생성함", "근거 없는 증권사·목표주가 문장을 답변에서 제거함"]
```

리포트 15건 중 **12건에서 sanitize 가 발동**했고, 검색 실패로 분류된 12건 중 **9건이
실제로는 이 경우**였다(검색은 성공). 사용자에게는 "데이터가 없다"로 보이지만 데이터는 있다.

**추정 근본 원인**: 답변에 등장한 증권사명을 Tool 근거와 대조하는 로직이, 근거가 있는
목표주가 문장까지 함께 제거한다. `_safe_answer_for_unsupported_event_claim` /
`sanitize_answer` 경로.
**수정 계층**: 검증기 (`app/agent/validator.py`)

### 4.2 Tool 열거형 인자에 없는 값 — 9건

**기대**: "현대차 배당금 얼마야?" → DB 에 배당 공시 135건 존재
**실제**: `get_disclosure_values(stock_code='005380', event_types=['배당'])` → `no_data`

DB 의 실제 `event_type` 값은 `dividend_matter`·`treasury_stock_status` 등 **영문**인데,
`DisclosureValuesInput.event_types` 에 유효값 목록이 없어 모델이 한국어로 추측한다.

**수정 계층**: Tool description (`app/agent/tools/disclosures.py` 의 인자 설명)
공시 유형 Recall@K 가 0.067 로 최저인 직접 원인이다.

### 4.3 정답 근거 미검색 — 36건 중 뉴스 3건은 색인 정합성 문제

뉴스 사건 하나에 `rag_documents` 가 **최대 12개** 존재하고, `is_current=false` 인
문서의 청크가 여전히 `is_active=true` 로 검색 대상에 남아 있다.

```
사건 7194(현대차 아세안 현대컵): 문서 12개, is_current 는 1개
비현행 문서의 활성 청크: 941건 (전체 뉴스 청크 4,433건의 21%)
```

라벨은 `is_current` 문서의 청크를 정답으로 지정했지만, 검색은 중복 문서의 청크를
반환한다. **데이터 정합성 문제**이며 운영 코드 수정 대상이 아니다(재색인 필요).

### 4.4 숫자·기간 오류 — 13건 (재무 전용)

두 갈래다.

1. **질문 자체가 모호** — `fin-03` "2025년 3분기 영업이익 얼마나 나왔어?"
   라벨은 3분기 *누적*(23.5조), Agent 는 3분기 *단독*(12.17조) 답변. 둘 다 옳다.
   → **평가 데이터 문제** (질문에 누적/단독 명시 필요)
2. **`expected_period` 검사가 과도** — `fin-02` 는 숫자·기간이 모두 맞았는데
   답변에 "누적"이라는 낱말이 없다고 실패. 질문이 "연간 매출액"이라 쓸 이유가 없다.
   → **채점기 문제**

`fs_div='OFS'`(별도)를 요청해 `no_data` 가 된 건도 있다(`fin-04`). DB 에는 CFS 만
적재돼 있다 — Tool 이 별도재무 미보유를 알리지 않는다.

### 4.5 제외 조건 위반 — 4건

`excl-05` 등에서 "실적 제외" 요구에도 실적 내용이 답변에 포함됐다.
11건 중 4건이라 준수율 약 64% — 목표(95%)에 크게 못 미친다.
**수정 계층**: 시스템 프롬프트

### 4.6 금지 Tool 호출 — 1건

`news-11` 에서 뉴스 질문에 `get_financial_facts` 를 호출했다.

## 5. 채점기·라벨 문제 (발견됨)

평가 수치를 높이려고 라벨을 바꾸지 않았다. 아래는 **기록만** 한다.

| 문제 | 건수 | 내용 |
|---|---:|---|
| 정답 식별자가 과도하게 좁음 | 12 | "배당 얼마나 줬어?" 처럼 특정 자료를 지정하지 않은 질문에 접수번호 1건만 정답으로 지정 → 정상 답변도 Recall 0 |
| 질문 모호(누적/단독 미명시) | ~4 | `fin-03` 류. 라벨과 다른 정답도 옳음 |
| `expected_period` 과잉 검사 | ~3 | 답변에 "누적" 낱말이 없다고 실패 처리 |
| 뉴스 정답 청크가 비현행 문서 기준 | 9 | §4.3 색인 중복 때문에 검색 결과와 어긋남 |

따라서 **검색 Recall@K 0.333 은 실제 검색 성능보다 낮게 측정된 값**이다.
공시·리포트·뉴스 Recall 은 라벨 보정 후 재측정해야 의미가 있다.

## 6. 최소 수정 제안 (실제 수정 안 함)

우선순위: 치명적 → 반복되는 중요 → 공통 계약 → 성능.
여러 계층을 한꺼번에 고치지 않고 **가장 근본적인 한 계층**만 지정한다.

| 순위 | 대상 | 계층 | 근거 | 기대 효과 |
|---:|---|---|---|---|
| 1 | 근거 있는 목표주가 문장까지 지우는 sanitize | **검증기** | 22건, 사용자에게 "데이터 없음"으로 보임 | 리포트·혼합 유형 답변 품질 직접 개선 |
| 2 | `event_types` 유효값을 인자 설명에 명시 | **Tool description** | 9건, 공시 Recall 0.067 의 직접 원인 | 공시 유형 전반 |
| 3 | 제외 조건 준수 규칙 강화 | **시스템 프롬프트** | 4건(준수율 64%), 치명적 | 부정·제외 유형 |
| 4 | 뉴스 중복 문서 재색인 | **데이터 정합성** | 비현행 활성 청크 941건(21%) | 뉴스 검색 정확도 |
| 5 | 라벨 보정(좁은 정답 식별자·모호 질문·기간 검사) | **평가 데이터** | 19건 내외 | 지표 신뢰도 |

금지 사항 준수: 질문별 예외 처리·특정 기업/기간 하드코딩·키워드 라우터·QueryPlan 복구·
custom StateGraph 추가는 어느 제안에도 포함하지 않았다.

**1·2번은 서로 독립적**이라 동시에 진행해도 충돌하지 않는다. 3번은 프롬프트 변경이므로
1·2번 적용 후 재측정하고 손대는 편이 안전하다.

## 7. 홀드아웃 실행 가능 여부

**아직 실행하면 안 된다.**

이유:

1. 치명적 실패 54건이 미해결이다. 지금 홀드아웃을 쓰면 개선 전 수치로 소모된다.
2. 라벨 문제 19건 내외가 남아 있어 **검색 지표가 실제보다 낮게 측정**된다.
   보정 없이 홀드아웃을 재면 비교 기준이 어긋난다.
3. §6 의 1·2번(검증기·Tool description)은 여러 유형에 공통으로 영향을 준다.
   이 둘을 고친 뒤 개발셋을 재측정하고, 그 다음에 홀드아웃 1회를 쓰는 순서가 맞다.
