# Phase 8 종목 문맥 회사명 누락 최소 수정 결과

## 범위

- 기준: PR #67이 병합된 `origin/main`
- 브랜치: `phase/8-stock-context-company-name`
- 대상 결함: 종목 화면 문맥에서 종목코드만 Agent 시스템 프롬프트에 전달되어
  모델이 회사명을 임의로 보완하던 문제
- 미실행: 전체 개발셋 120문항, 홀드아웃, 배포

## 원인

`_stock_context_block()`은 `stock_code`만 받아 시스템 프롬프트에 종목코드만
기록했다. 따라서 Tool 호출에는 올바른 코드가 들어가도 모델이 코드에 대응하는 회사명을
기억에 의존해 생성할 수 있었다. 실제 이전 결과에서 `005380`을 삼성전자로 표현한 사례가
이 경로에서 발생했다.

## 수정 내용

- 기존 `QaRuntimeContext`에 `company_name`을 추가했다.
- 기존 `FactsService`의 Supabase 연결을 재사용해 `stocks.code`와 정확히 일치하는
  `stocks.name`을 조회한다. 종목별 매핑은 추가하지 않았다.
- stock context에 `종목코드 / 공식 종목 마스터 회사명`을 함께 전달한다.
- 회사명이 조회되지 않으면 `확인 불가`로 표시하고 종목코드만 보고 회사명을 추측하거나
  만들지 말라고 명시한다.
- Agent 구조, Tool 구조, Retriever, 다른 프롬프트 규칙은 변경하지 않았다.

## ctx-03·ctx-06 실제 Agent 실행

2026-07-27에 개발셋에서 두 ID만 선택해 각각 1회 실행했다. 실행 중 코드와 프롬프트는
수정하지 않았으며 홀드아웃 파일은 열지 않았다.

### ctx-03

시스템 프롬프트의 stock context:

```text
현재 종목 문맥(서버 확정):
- 종목코드: 005380
- 종목(코드 / 공식 회사명): 005380 / 현대차
- 사용자가 종목을 말하지 않은 질문은 이 종목에 대한 질문이다.
- 종목을 되묻지 않는다. Tool 의 stock_code 인자에 이 코드를 그대로 넣는다.
- 사용자가 다른 종목을 명시한 경우에만 그 종목을 쓴다.
```

Tool trace:

```text
get_stock_prices({"stock_code": "005380"}) → ok (1,645ms)
```

최종 답변은 `현대차(005380)`로 표현했다. 다른 회사명으로 변경하거나 임의 회사명을
추가하지 않았다. 필수 Tool과 `stock_code` 인자 채점은 모두 통과했고 타 종목 출처는 0건이다.

- 입력 토큰: 14,368
- 출력 토큰: 58
- 추정 비용: **$0.005840**

최종 답변은 `SK하이닉스`로 표현했다. 다른 회사명으로 변경하거나 임의 회사명을
추가하지 않았다. 필수 Tool과 `stock_code` 인자 채점은 모두 통과했고 타 종목 출처는 0건이다.

## 전체 재실행이 불필요한 근거

수정 범위는 요청별 runtime context의 회사명 조회와 stock context 문자열 결합뿐이다.
Tool 선택·실행, 검색, 채점, 다른 프롬프트 규칙은 바뀌지 않았다. 결함을 직접 재현하는
`ctx-03`, `ctx-06` 실제 실행과 관련 context 테스트가 모두 통과했으므로, 이 변경을 위해
전체 120문항을 다시 실행할 추가 근거는 없다. 전체 재실행은 요청상 금지된 범위이기도 하다.

## 홀드아웃 준비 여부

**준비됨.** 관련 회귀와 두 실제 문항은 통과했으며 홀드아웃 데이터에는 접근하지 않았다.
홀드아웃 실행은 별도 승인된 평가 단계에서만 수행한다.
