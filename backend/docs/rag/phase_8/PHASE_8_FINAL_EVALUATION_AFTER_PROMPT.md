## 4. Solar Judge

| 항목 | 값 |
|---|---|
| **Solar 호출 성공** | **120건** |
| **키워드 폴백** | **0건** |
| grounded=false (참고 지표) | 0건 |

첫 채점 시 `report-07` 1건이 `parse_error: JSONDecodeError` 로 폴백했으나,
재채점에서 정상 판정돼 최종 0건이다. judge 는 temperature=0 이고 결과를 캐시하므로
동일 입력은 재호출하지 않는다.

`grounded` 는 prompt.md 지시대로 참고 지표로만 보고하며 통과 조건에 넣지 않았다.
현재 judge 입력에는 출처의 제목·종류·날짜만 들어가고 본문·수치는 들어가지 않아,
`grounded` 판정의 신뢰도는 제한적이다(PR #66 에서 확인한 한계).

## 5. 확인된 회귀

### A. `fin-10` — "단독" 질문의 `fs_div` 오선택 (기존 불안정성 악화)

- 증상: "SK하이닉스 2025년 3분기 **단독** 영업이익" 질문에 `fs_div=OFS`(별도)로
  호출 → `no_data`. 프롬프트에는 "'단독'은 별도재무제표가 아니라 3개월치라는
  뜻이므로 `fs_div` 는 CFS 유지" 규칙이 그대로 살아 있다(prompts.py:41,43).
- 재현: 새 프롬프트 3/3 회 모두 OFS(결정적).
- **원인 판정**: 구 프롬프트로도 3회 중 1회 OFS 가 나온다 → 리팩터링이 만든 새 버그가
  아니라 **원래 있던 불안정성이 이번 프롬프트에서 더 자주 발현**된 것.
- 같은 유형인 `fin-04`(삼성전자 3분기 단독)는 CFS 로 정확히 호출됐다.

### B. `news-03`·`news-17` — `relative_period` 미지정 (신규 회귀)

- 증상: "갤럭시Z 폴드8 이슈", "갤럭시 워치9 뉴스" 질문에서 `relative_period` 를
  넣지 않아 기간 필터 없이 검색 → 오래된 클러스터(3xxx번대) 반환.
- 재현: 새 프롬프트 4/4 미지정, **구 프롬프트 4/4 지정**.
- **원인 판정**: 프롬프트 리팩터링이 만든 **재현 가능한 신규 회귀**. 다만 해당 규칙은
  `"최근/요즘/최신"이라고 하면` 이라는 조건부라, 그 단어가 없는 이 두 질문은 원래
  규칙 적용 대상이 아니다 — 구 프롬프트가 규칙 밖에서 관대하게 동작하던 것이
  사라진 형태다.

### C. `ctx-04` — 종목명 미언급 (신규, 경미)

"이 종목 목표주가 얼마야?" 답변이 목록으로 바로 시작해 종목명("두산에너빌리티")을
언급하지 않았다. 도입부 금지 지시의 부작용. 정확성 문제는 아니고 답변 완결성 문제.

### D. (회귀 아님) 문맥 종목의 회사명 오기 — 기존 제품 결함

`ctx-03`(현대차 질문 → "삼성전자(005380)"), `ctx-06`(SK하이닉스 질문 → "이
회사(삼성전자)")처럼 **종목코드는 맞게 쓰면서 회사 이름을 지어낸다.**
이전 final-dev 에서도 `ctx-03` 이 동일하게 "삼성전자(005380)"라고 답했으므로
이번 회귀가 아니다.

- 근본 원인: `_stock_context_block()` 이 프롬프트에 **종목코드만** 싣고 회사명을
  주지 않는다(prompts.py:215-230). 모델이 코드를 보고 회사명을 기억으로 채운다.
- 이번 라운드는 평가만 수행하므로 고치지 않았다. **다음 라운드 최우선 수정 후보.**

## 6. 실행 후 수정한 것 (기록)

실행 중에는 아무것도 고치지 않았다. 실행 완료 후, 평가 스크립트의 환경 실패 분류에
결함이 있어 고치고 **저장된 기록만 재채점**했다(Agent 재실행 없음).

- 결함: `RateLimitError` 로 답변이 생성되지 못해도 `stop_reason` 이 `completed` 라
  환경 실패로 잡히지 않아, 외부 장애 3건이 제품 실패로 집계됐다.
- 수정: 답변 본문의 모델 API 오류 문자열(`RateLimitError`, `Model call failed
  after`, `Error code: 429` 등)도 환경 실패로 판정하고, 통과율 분모에서 제외.
- 제품 코드·프롬프트·gold·devset 은 변경하지 않았다.

## 7. 판단

### 새로운 공통 치명적 버그: **없음**

- 안전성 지표(존재하지 않는 인용, 타 종목 혼입, 실제/전망 혼동, 답변 불가 오답)는
  전부 0 이다.
- 확인된 회귀 3건(§5-A/B/C)은 모두 **개별 문항 단위**이며, 여러 유형에 공통으로
  퍼지는 구조적 결함이 아니다.
- 외부 장애를 걷어낸 Agent 지표는 이전 이상이다.

### 코드 동결: **가능**

정확성·안전성 회귀가 없고, 남은 회귀는 개별 문항 수준이다. prompt.md 지시대로
100% 를 목표로 추가 튜닝하지 않는다.

### 홀드아웃 진행: **가능**

다만 실행 전에 다음 두 가지를 권고한다.

1. **Rate limit 대비** — 이번 실행에서 3건(2.5%)이 429 로 유실됐다. 홀드아웃은
   40문항뿐이라 같은 비율이면 1건이 통째로 날아간다. 문항 사이 간격을 두거나
   재시도 여유를 두고 실행할 것.
2. **상대 날짜 gold preflight** — PR #65 에서 준비한
   `preflight_check_relative_gold_validity()` 를 홀드아웃 케이스에 먼저 호출해
   `should_abort` 를 확인할 것(이번 라운드에서 홀드아웃은 열지 않았다).
