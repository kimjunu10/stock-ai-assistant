## 1. round2 원인 진단 재검증

round2(PR #59)는 뉴스 검색 종료일 경계 결함을 고쳤고 비현행 활성 청크를 945→0 으로
정리했다. round3 에서 같은 방식으로 재확인한 결과:

- **활성 상태는 여전히 대체로 건강하다**: `is_current=false AND is_active=true` 인 청크가
  945→0 이었던 것이, round2 PR 머지 이후 라이브 뉴스 파이프라인이 계속 돌면서 **9건**
  다시 생겼다(운영 결함이 아니라 정리 스크립트가 일회성이라 이후 색인분은 자동으로는
  안 지워짐 — 이번 라운드는 코드·데이터 수정 금지라 그대로 두고 기록만 한다).
- 이 9건이 실제 검색 실패와 연결되는지 다시 확인했다. round3 뉴스 Retriever 실패 7건 중
  gold 문서 자체는 **전부 `is_current=true`(정상 현행)** 였다. 즉 이번 라운드의 뉴스
  검색 실패는 색인 정합성 문제가 **아니고** 순수 의미 검색 순위 문제다(§5).

**고유 실패 문항: 24건.**

### 3-A. "제외 조건 위반" 4건 — 전부 그레이더 오탐, 실제 위반 0건

네 건을 각각 원문 대조로 확인했다.

- **`report-10`**: "증권사 목표주가와 전망은 예측치이며 **확정 실적이 아님**을 유의" —
  forbidden_claims 의 "확정"이 나온 문장인데, 정확히 **부정문으로 규칙을 지켰다**.
  `_NEGATION_MARKERS` 목록에 "아닙니다"는 있는데 "아님"이 없어 매처가 못 잡았다.
- **`excl-05`**: "한화오션의 최근 **실적 외** 주요 이슈는..." — "실적 빼고" 요청을
  정확히 지켜 실적 얘기를 전혀 안 했다. "~외" 표현이 부정 마커 목록에 없다.
- **`disc-13`**: "주관 증권사: 삼성증권, 신한투자증권, KB증권" — forbidden_claims
  가 막으려던 것은 "증권사 목표주가·투자의견"인데, 공시 문서의 **주관사 필드**까지
  같은 단어("증권사")로 걸렸다. 라벨이 지나치게 넓다.
- **`na-05`**("이 종목 사도 돼?"): "투자 판단에 필요한... 직접적인 매수·매도 추천은
  하지 않습니다" — 정확히 투자 추천을 거절했는데 forbidden_claims 문자열이 답변
  설명 문장에 그대로 등장해 걸렸다.

**4건 모두 Generation 결함이 아니라 그레이더(`_claim_asserted`)의 부정 마커 목록이
좁아서 생긴 채점 오탐이다.** 코드는 고치지 않았다(이번 라운드 금지 범위) —
다음 라운드 최소 수정 후보로만 기록한다.

### 3-B. "불필요 Tool 호출" 5건 — 답변은 정확함

`na-01/04/06/08` 은 답변 불가 질문에 Tool 을 먼저 부르지만 결과는 대체로 정확하다
("확인할 수 없습니다"). 다만 `na-06`(삼성전자 CEO 연봉)은 이번 라운드에서 품질이
약간 떨어졌다 — 라벨은 "보유 데이터에 없다고 밝혀야 한다"인데 실제 답변은 "포함되어
있을 가능성이 있다"며 원문 확인을 유도했다. 그레이더의 `unanswerable_handled` 휴리스틱은
이를 통과시켰지만, 라벨이 요구한 명확한 "없다" 진술을 완전히 충족하지 못한 것으로 판단한다.
계층 분류상 실패로는 안 잡히지만 정직하게 기록해 둔다.

### 3-C. Validator 계층 7건 — 전부 정탐 확인

`mix-09`(목표주가 140,000원이 stated 허용값 밖), `report-08/09`(근거 없는 숫자),
`na-02`(999999 종목 관련 차단) 는 이전 라운드와 동일한 정탐 패턴이다.
`mix-15` 는 검증기가 목표주가를 정확히 차단했고, 별도로 `get_stock_prices` Tool 이
**일시적 API 오류**를 반환해 Agent 가 이를 정직하게 답변에 밝혔다(외부 환경 이슈,
재현성 없는 일회성으로 판단).

## 5. 뉴스·리포트 검색 실패 상세 — 실제 원인

### 뉴스 7건 (news-03/04/09/13/14/15/19)

모두 gold 문서가 `is_current=true`(정상 현행)이고, 날짜 필터 문제(round2 에서 고친
종료일 경계)도 아니다. 예: `news-03`("갤럭시Z 폴드8 이슈") 는 `date_from/date_to` 없이
쿼리만으로 검색했는데도 gold(cluster 7189, "구독 서비스 개편")가 상위 8건에 들지 않고
비슷한 시기의 다른 갤럭시 폴드8 관련 뉴스들이 상위를 차지했다. **순수 의미 검색 순위
문제**다.

### 리포트 4건 (report-06/08/09/15)

- `report-06`: `broker`(대신증권) 인자를 여전히 안 넘긴 경우가 있었다(round2 에서
  docstring 을 보강했지만 100% 는 아님).
- `report-08`: `broker` 필터는 걸렸는데 최신(2026-07-08) 대신 오래된(2026-05-04)
  리포트가 검색됐다. round2 에서 이미 "의미 검색 품질 문제, 색인은 정상"으로 확인한
  케이스와 동일하다.
- `report-09/15`: 검증기가 근거 없는 목표주가를 정확히 차단한 결과이지 검색 자체의
  새로운 결함은 아니다(§3-C).

`disc-11`(공시)은 이번 라운드에 round2 회귀 때와 다른 공시 문서를 반환했다.
`search_disclosures` 가 의미/키워드 검색 기반이라 **동일 질문에도 실행마다 결과가
달라질 수 있음**(비결정성)을 시사한다. 코드 결함이라기보다 이 Tool 의 검색 안정성
자체가 다음 라운드에서 살펴볼 대상이다.

## 6. 리포트 질문 구분 (prompt.md §요구사항)

devset 의 리포트 문항 15개(report-01~15)를 전수 확인한 결과 **전부 증권사·날짜 중
최소 하나가 질문에 명시돼 있다.** "종목만 있고 어떤 리포트인지 불명확한" 질문이나
"최근 리포트 목록" 요청 유형은 이번 devset 에 포함돼 있지 않다. 따라서 이번 라운드는
"질문 명확화 필요" 계층에 해당하는 사례가 0건이다 — Agent 가 명확화를 안 해서가
아니라 devset 설계상 그런 질문이 없었다.

## 7. 남은 가장 큰 문제 5개

1. **뉴스·리포트 의미 검색 순위** — gold 문서는 정상 색인·활성인데 상위 후보에
   들지 못하는 사례가 뉴스 7건 + 리포트 2건(report-06 잔여분 포함 시). 임베딩·RRF·
   reranker 변경 없이는 해결 범위 밖(§4·§5 금지 사항).
2. **그레이더 부정 마커 목록의 한계** — "아님", "~외" 같은 부정 표현이
   `_NEGATION_MARKERS` 에 없어 정상 답변 4건이 "제외 조건 위반"으로 오탐(§3-A).
3. **`search_disclosures` 검색 비결정성** — 동일 질문(disc-11)이 라운드마다 다른
   공시를 반환한다. 원인 불명, 재현 테스트 필요.
4. **forbidden_claims 라벨 과잉** — disc-13 처럼 문맥상 다른 의미(공시 주관 증권사)
   까지 같은 단어로 막는 라벨이 남아 있다.
5. **`na-06` 류 애매한 회피 답변** — 라벨이 명확한 "없다" 진술을 요구하는데 "가능성이
   있다"며 원문 확인을 유도하는 답변이 그레이더는 통과하지만 품질은 떨어진다.

## 9. 홀드아웃 실행 가능 여부

**아직 이르다.** 종료 기준 8개 중 겉보기엔 1개 미달(제외 조건 준수율)이지만 실측
결과 그 미달은 채점기 결함이며 실제 Generation 위반은 0건이다. 그러나:

- 뉴스·리포트 의미 검색 순위 문제가 여전히 24건 중 11건(7+4)을 차지하며 미해결이다.
- `search_disclosures` 의 비결정성 원인이 아직 규명되지 않았다.

이 두 가지가 정리되기 전에는 홀드아웃을 열 근거가 부족하다고 판단한다.
